## Findings considered and rejected

- **Upstream issue for constant-folded intermediate JSON inspection**: not
  planned by maintainer decision. Plan 063 documents the verified local behavior
  and working native forms only; it creates no issue and pins no wrong-result
  test.
- **Local workaround for the current DuckDB `main` compatibility canary**:
  rejected for now. Do not add a dual-version shim or permissive compatibility
  layer against a moving internal API; wait for the release/ref-next window and
  work against its concrete branch. The existing scheduled canary remains the
  signal. No implementation plan was created.
- **One generic shredded-introspection framework for keys, type, and array
  length**: rejected. Their correctness sources differ: keys merges residual
  names with manifest state, array length reads skeleton cardinality, and root
  type is already residual-equivalent. Plans 060/061 keep separate scalars and
  share only the signature initializer.
- **Lane validity or spill bits as the source for whole-document keys**:
  rejected. The manifest records what was actually stripped; lane NULL also
  represents absence, JSON null, diversion, and list skeleton cases.
- **Lowering the shape-cache default instead of fixing allocation timing**:
  rejected. Capacity controls hit rate and does not explain reserving 64
  permutation elements in every unused slot; plan 059 fixes that root cause and
  keeps the public capacity setting.

- **Container-span / object-checkpoint trust** (reader walks navigation metadata
  without re-deriving it): produces a *bounded* wrong decode on a corrupt blob but
  **never** an out-of-bounds read (every access is blob-bounds-checked). By design
  — full integrity is `jsono_validate`'s job. Not bug-level.
- **`.DS_Store` files in the working tree**: correctly `.gitignore`d and not
  tracked (`git ls-files` is clean). Non-issue.
- **Format-doc constants vs code** (version=4, tag table, bit widths, DEC60
  packing, struct sizes, `OBJECT_CHECKPOINT_STRIDE`): all verified to match
  `src/include/jsono.hpp`. No mismatch (the only stale doc is the agent-manual
  body layout — see plan 002).
- **Stale removed-concept references** (`JSONO` alias, `JSON_TAPE`, fp-in-names,
  union-merged type, `waddle`, indexed/bitset manifests): no live references
  outside the historical `bench/optimization-log/`.
- **Mixed object↔scalar kind in the plain ordered `group_merge`**: NOT rejected on
  purpose — RFC 7396 defines scalar-replaces-object wholesale and ORDER BY makes
  it deterministic. Only the keyed `_max`/`_min` form must reject it (and does, in
  both update and combine). Not a gap.
- **Manifest-narrowing fail-loud coverage**: already exhaustive in
  `test/sql/jsono_shredded_cast_guard.test` (every reader, plain + shredded,
  serializer round-trip, validate). Plan 003 probes only the narrower NULL-body
  variant; plan 004 deliberately does not duplicate the narrowing tests.
